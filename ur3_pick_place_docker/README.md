# Moxynova Lab Automation Scaffold

This repository now contains a ROS 2 lab automation workspace scaffold under `src/`.

The workspace is structured around a simulated lab robot stack for:

- robot description and Gazebo simulation
- control and bringup
- MoveIt, navigation, and manipulation
- perception and vision interfaces
- task planning, scheduling, and protocol execution
- sample tracking, inventory, and data management
- device interfaces and instrument drivers
- safety, monitoring, logging, and HMI
- tests, benchmarks, and demos

## Scaffold Source

The workspace layout is generated by:

```bash
bash scaffold_lab_workspace.sh
```

That script creates the package folders, package manifests, starter placeholder files, and the Gazebo world package layout.

## Container Usage

Build the image from the repository root:

```bash
docker build -t moxynova-lab .
```

Allow the container to connect to the host X server for Gazebo:

```bash
xhost +local:
```

Run the container:

```bash
docker run --rm -it \
  --name moxynova_runtime \
  --net=host \
  --ipc=host \
  -e DISPLAY=$DISPLAY \
  -e QT_X11_NO_MITSHM=1 \
  -e LOCAL_UID=$(id -u) \
  -e LOCAL_GID=$(id -g) \
  -v /tmp/.X11-unix:/tmp/.X11-unix:rw \
  moxynova-lab
```

The default container command will:

- launch Gazebo with `pick_and_place_demo.world`
- use the UR robot description with an attached Robotiq 2F-85 visual gripper
- launch MoveIt without RViz
- run `lab_demo_tasks pick_place_moveit_action`

If you want RViz as well, add `-e LAUNCH_RVIZ=true` to `docker run`.

If the container is already running and you want to rerun only the demo node:

```bash
docker exec -u developer -it moxynova_runtime bash -lc '
source /opt/ros/jazzy/setup.bash
source /workspaces/moxynova_ws/install/setup.bash
export HOME=/home/developer
export XDG_RUNTIME_DIR=/tmp/runtime-developer
export ARM_TRAJECTORY_ACTION=/scaled_joint_trajectory_controller/follow_joint_trajectory
ros2 run lab_demo_tasks pick_place_moveit_action
'
```

To stop the running container:

```bash
docker stop moxynova_runtime
```

Remove the temporary X server permission after closing the container:

```bash
xhost -local:
```

## Package Roles

### Core robot packages

- `lab_robot_description`
  Stores the robot URDF/Xacro, visual meshes, RViz profiles, and description-side configuration.
- `lab_robot_gazebo`
  Stores Gazebo launch files, world files, reusable lab models, and plugin placeholders.
- `lab_robot_control`
  Holds controller configuration, controller launch files, and future ros2_control C++ nodes.
- `lab_robot_bringup`
  Orchestrates startup of the robot stack from Python launch and bringup helpers.
- `lab_robot_moveit_config`
  Holds MoveIt configuration, SRDF files, launch files, and RViz planning profiles.

### Motion and perception

- `lab_navigation`
  Navigation stack package for maps, behavior trees, navigation launch files, and navigation-side C++ nodes.
- `lab_manipulation`
  Manipulation stack package for grasp profiles, manipulation launch files, and manipulation-side C++ nodes.
- `lab_perception`
  Perception package for sensor processing, model assets, and future C++ perception nodes.
- `lab_vision_interfaces`
  ROS interfaces package for perception-facing messages, services, and actions.

### Planning and orchestration

- `lab_task_planning`
  High-level planning package with workflows, plans, behavior trees, and Python orchestration modules.
- `lab_workcell_manager`
  Manages workcell definitions, stations, and their launch/config structure.
- `lab_scene_manager`
  Manages named lab scenes and scene-level launch/configuration files.
- `lab_digital_twin`
  Holds digital twin models, synchronization rules, and twin-side orchestration modules.
- `lab_protocol_executor`
  Intended for protocol playback and execution workflows.
- `lab_scheduler`
  Intended for job scheduling, queueing, and run coordination.
- `lab_state_machine`
  Intended for explicit system state transitions and operational modes.

### Data and tracking

- `lab_inventory_manager`
  Tracks consumables, carriers, fixtures, and stock records.
- `lab_sample_tracking`
  Tracks samples, containers, and traceability state across workflows.
- `lab_data_manager`
  Holds database layout, schemas, and data service scaffolding.

### Devices and interfaces

- `lab_device_interfaces`
  ROS interfaces package for device commands, states, and asynchronous operations.
- `lab_instrument_drivers`
  Driver-facing package for vendor adapters, driver config, and driver launch files.
- `lab_msgs`
  Shared project-wide messages, services, and actions not tied to one subsystem.
- `lab_utils`
  Shared utilities, scripts, and helper launch/configuration files.
- `third_party`
  Vendor code, local patches, and CMake integration placeholders for external dependencies.

### Operations and observability

- `lab_safety_system`
  Safety package for safety policies, enforcement nodes, and safety launch/config files.
- `lab_monitoring`
  Monitoring package for dashboards, alert definitions, and runtime monitoring layout.
- `lab_logging`
  Logging package for log routing, pipelines, and logging-side configuration.
- `lab_hmi`
  Human-machine interface package for UI assets and HMI launch/configuration.
- `lab_remote_ops`
  Remote operations package for remote clients and remote supervision tooling.

### Validation and examples

- `lab_tests`
  Integration and system test scaffolding, fixtures, and test launch files.
- `lab_benchmarks`
  Benchmark package for reproducible performance scenarios.
- `lab_demo_tasks`
  Demo workflows, plans, behavior trees, and example tasks for the simulated lab.

## Package Types

The scaffold uses package types based on intended responsibility:

- `ament_cmake`
  Used for description, simulation, control, driver, safety, benchmark, and test-oriented packages.
- `ament_python`
  Used for orchestration, planning, management, monitoring, data, HMI, and remote operations packages.
- interface packages
  `lab_msgs`, `lab_device_interfaces`, and `lab_vision_interfaces` use `msg/`, `srv/`, and `action/`.

## World Data

The old factory content is not treated as an active package in the new layout.

Only the world-relevant assets were carried into:

- `src/lab_robot_gazebo/worlds/lab_factory.sdf`
- `src/lab_robot_gazebo/models/`

This makes `lab_robot_gazebo` the single place for the simulated lab environment.
